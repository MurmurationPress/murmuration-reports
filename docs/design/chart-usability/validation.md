This record covers the bounded date-X chart usability milestone on `feature/chart-usability`. It is implementation evidence for synthetic fixtures; it does not qualify physical print, EPUB readers, assistive technology or accessible PDF.

## Native Obsidian exercise

The disposable Linux vault was opened in Obsidian `1.13.7` (Chrome `150.0.7871.212`, Electron `43.3.0`) with the candidate plugin. The driver exercised the manager with no startup exceptions reported. It verified the grouped editor and visible field labels, recursive discovery under nested folders, exact property keys alongside generated labels/types, mixed and missing-property diagnostics, editable label override retention after a key change, invalid tick feedback/focus, generation and preview, preservation of comments/body/unknown YAML fields, and legacy paired-bound compatibility. It inserted an intermediate observation and confirmed explicit-pair output stability; renaming a referenced note caused an error without rewriting assets or falling back to a predecessor. It then disabled Reports and reopened the saved SVG/Markdown transclusions with the plugin unloaded.

The product-generated SVG SHA-256 was `776d2b6b7f8b8eee45d6b868a635d0d3b3dabcc631de991b7440e20b31ed4b00`; the explicit comparison table SHA-256 was `4b8e21c850fb9ee2e0110d6b96126a8602fecca691f9056c819ad923517c075a`. These checks use a disposable vault and synthetic notes only. Adapter tests do not establish native Obsidian behavior; the exercise above used the actual desktop application.

## Compiler publication matrix

The exact saved SVG and Markdown table generated by the candidate plugin were published through Codex Press commit `394cf109f035194b440e3b37d75de06e49fe074d`. The harness ran with the Reports plugin disabled and read synthetic data recursively from the declared dataset folder. Figures below are measured in the resulting PDF using PyMuPDF. “Minimum text” measures SVG text at final page size; essential line weights are measured in points. Direct SVG conversion is not used as placement evidence.

| Requested width/profile | Actual PDF width | Chart page | Minimum SVG text | Minimum essential stroke | Table pages | EPUB |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 3.5 in / KDP 6×9 | 251.993 pt (3.4999 in) | 7 | 8.40 pt | 0.787 pt | 8–11 | EPUBCheck passed; exact SVG payload; all 80 rows |
| 4.1 in / KDP 6×9 | 295.200 pt (4.1000 in) | 8 | 9.84 pt | 0.923 pt | 8–12 | EPUBCheck passed; exact SVG payload; all 80 rows |
| 5.5 in / draft A4 | 396.000 pt (5.5000 in) | 7 | 13.20 pt | 1.238 pt | 8–10 | EPUBCheck passed; exact SVG payload; all 80 rows |

For all three builds, PDF text extraction found every visible SVG label, the chart and external caption stayed on the same page, no text extended outside the page, and each of the 80 table row markers appeared exactly once with the expected `+5.00` delta. Every chart and table page was rendered in grayscale and visually inspected. Series identity remained readable through matching dash/marker styles; titles, units, axis tick labels, legend and both captions were present. The 3.5-inch page is the limiting case and its smallest SVG text remains above the design target of 8 pt.

EPUB validation establishes package validity, exact SVG payload preservation, the authored width declaration and table content. It does not establish layout or accessibility in any EPUB/Kindle reader. No physical proof, reader or assistive-technology qualification was performed, and the compiler PDF has no established accessible tagging.

The reproducible harness is `scripts/verify-first-milestone-publication.ts`; the measurement and EPUB audit is `scripts/audit-chart-usability-publication.py`. Synthetic run artifacts remain under `/tmp` and are not committed.
