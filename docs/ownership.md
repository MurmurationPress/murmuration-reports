# Ownership and recovery

Definitions are identified by their vault-relative path. Existing schemas and renderer output bytes are unchanged. A receipt has `version: 1`, `definitionPath`, `outputPath` and a lowercase SHA-256 `digest` of the authorised saved output. Missing receipts cannot affect display or compilation.

A state table's sole canonical ownership comment must be on its own final line, with the exact URI-encoded definition path. A substring, duplicate comment, conflicting owner or non-canonical encoding is rejected. Legacy SVGs have no ownership proof. Explicit adoption validates the declared destination, asset type, all current source/definition collisions and any former ownership. Consent is a one-use in-memory inspection bound to the asset and definition digests. The final write rechecks those digests. The dialog has Cancel, raw-content inspection and Open existing output; it never executes SVG markup.

An existing receipt must parse and match the output digest/path. A corrupt receipt or externally changed owned asset is blocked even by adoption: recover the original asset/receipt, or choose a new output path. Adoption is not an override for another report. Path repair is permitted only when the former definition is absent and no current definition competes for the destination. It still requires an explicit confirmation. Receipts do not carry hidden report configuration.

Before replacement, a verified copy is created adjacent to the output as `<output>.murmuration-report-backup` (then `.1`, `.2`, etc.). Backups contain the exact original bytes. They are not Markdown observations and are not deleted automatically. Back them up with the vault; inspect/recover them manually if needed. Undo is not provided; copying a backup back to its original location is a deliberate recovery action. Restore the corresponding receipt or explicitly resolve ownership before another generation.

The coordinator computes output in memory, checks current Markdown definitions and observations from fresh file reads, snapshots content and inventory, then rechecks before mutation. All its requests are serialised. `Vault.process` performs compare-and-replace for text files; creates fail if occupied. Every output and receipt is read back before success. Receipt failure is generation failure, with best-effort conditional compensation and explicit recovery paths. Concurrent edits are never overwritten by compensation. Disabling Reports cancels queued work and subsequent normal writes; compensation may still attempt to restore an in-flight operation.

Obsidian offers no multi-file transaction or vault-wide lock, and delete has no compare-and-delete primitive. Rechecks cannot prevent an external sync write between all individual operations. Abrupt process termination can leave a new output without a receipt, a mismatched pair, or a backup requiring recovery. These fail safely on subsequent regeneration instead of being reported as ownership proof. The plugin does not claim crash-atomic generation. Empty output directories may remain after a failure.

The conservative Stage 1 command path reads the Markdown inventory for collision safety, including when metadata caches lag. This work happens only for explicit commands; it is not an event-driven index. A concurrent Markdown edit anywhere in that inventory may require retry. Stage 2 can improve indexing without weakening mutation-time checks.
